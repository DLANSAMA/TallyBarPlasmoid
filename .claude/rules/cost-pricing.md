# Cost scan, token math, pricing and caches

Area contracts moved out of the root CLAUDE.md; they load only when a matching file is touched.

**Cost scan is compute-concurrently / apply-after, double-bounded — don't serialize or collapse it.** Kicked off at the very top of `build_snapshot` (overlaps network fetches), applied only after a clean `await cost_scan`. Timeout → `cost_summary_timeout` diagnostic, scan skipped entirely. A second cooperative deadline threads through `compute_local_cost_summaries(deadline)`. Tests patch `backend.compute_local_cost_summaries` (not `apply_cost_summaries`). **Providers are isolated:** a non-timeout exception from one provider's summary sets that provider to `None` and records `summaries["_errors"][provider] = "<ExcClass>: <message>"` (`COST_SUMMARY_ERRORS_KEY`, present only when one failed); the others still return. `TimeoutError`/`LogScanIncomplete` still abort the whole scan. `apply_cost_summaries` never treats `_errors` as a provider, and `update_cost_archive` skips it and keeps a failed provider's recorded month. → `tests/test_antigravity_ledger_integrity.py::test_one_failing_provider_keeps_the_others`, `::test_error_map_is_neither_a_provider_nor_an_archived_month`.

**`diagnostics.timings` reports per-phase wall clock (ms) in every snapshot** — `cookies`, `providers`, `cost_scan`, `total`. Read it before guessing where a slow refresh goes.

**Token semantics are verified — don't "simplify":**
- Ledger: `o = t + x` (total output = thinking + response); bill `u·input + c·cache + o·output` once.
- Volume = `u + c + o` (includes cached — industry standard); cost bills cache at the *discounted* rate.
- Antigravity ledger cache reads are billed PER ENTRY in every key namespace (`:` / `@` / `#` / `cli:`) — each entry is one API call and pays for the cache it re-reads. Never collapse a conversation to its peak `c`: the agy RPC and the CLI steps rows carry identical per-call values, so namespace-specific accounting makes cost depend on the capture path and shift when CLI ownership flips. → `tests/test_cli_usage.py::test_cache_read_billed_per_call_*`
- `usage_cost_usd` local-log shapes: Anthropic cache additive (never subtract from input); OpenAI subsets; Gemini `thoughts`+`tool` additive (the `tool` add is NOT double-counting).
- Anthropic 1h cache writes = 2× input (`cache_write_1h`), NOT 1.25×. `_litellm_to_tallybar` **synthesizes** `cache_write_1h = 2× input` for any Anthropic model the live catalog omits — don't drop that synthesis.
- Claude dedup: keep the FINAL (max-`output_tokens`) streamed line per message, not first-seen. The key is `message.id`, then `requestId`, then the line uuid: every content-block line of a message carries the full usage, and some transcripts have NO `requestId` on any line (some also repeat another session's messages), so a requestId-first key bills such a message once per line and a repeated one again. → `tests/test_accounting.py::test_requestid_less_messages_*`
- Claude subagent output estimate: a request in a `subagents/` transcript with no final-usage line (no line with a non-null `stop_reason` or `usage.output_tokens_details`) bills `max(logged, visible_chars // 4)` output, where visible chars are text plus compact tool_use input JSON, summed per line uuid. The added tokens are reported as `estimatedOutputTokens` (cost-section tooltip). Main-session transcripts are never estimated. → `tests/test_accounting.py::test_subagent_*`
→ `tests/test_accounting.py`, `tests/test_cli_usage.py`, `tests/test_pricing_data.py`.

**`typeBreakdown` (per-window split by usage type) must sum to each window's total.** `pricing.usage_split` prices a record ONCE through the same `_cost_terms` list `usage_cost_usd` sums (prompt tier chosen per request first), and tags each term input / output / cacheRead / cacheWrite — never price the types separately (the tier and the cost would drift from the total). Anthropic cache is additive; the OpenAI/xAI/Gemini cached subset moves from input to cacheRead; Gemini `tool` is input; thoughts/reasoning are output. Tokens a record's explicit total holds beyond its typed parts go to `unsplit`, so the split always adds up. Each summarizer adds a record's split at EXACTLY the sites its today/7d/30d totals accumulate — move one, move both. Grok's archived days carry `types`; legacy days split tokens from in/out/cached and share the day's cost by rate weight. Antigravity entries split u/o/c (no cache writes). Cache writes found only in the nested `cache_creation` 5m/1h breakdown are billed but not counted as tokens — the parse caches keep or drop a record by `usage_token_total > 0`, so counting them changes cache contents without a parse-version bump. `_terms_cost` adds the terms in order, never `sum()` (Python 3.12+ compensates and moves totals by an ulp). → `tests/test_type_breakdown.py`.

**Monthly cost archive (`~/.tallybar/cost_archive.json`) is append-only — past months freeze.** `update_cost_archive` (providers/cost.py, best-effort at the end of `compute_local_cost_summaries`) upserts only `months[<current>]` from each summary's in-month buckets, so the 35-day Antigravity prune can't erode prior months. **Change-gated** like `new_marks != marks` (skip the write when the current-month dict is unchanged); atomic 0600 + `.bak` mirror + `.corrupt` quarantine loader (never-load-into-empty); flock bounded by the cost-scan deadline. First month recorded carries `"partial": true`. → `tests/test_cost_archive.py`.

**Parse caches (`~/.tallybar/cache/{codex,grok,gemini}_logs.json`, and the Claude store `claude_logs.{hot,sNN}.json`) must be pure functions of file bytes.** `_parse_*_file` stores all-time records with no window baked in; summarizer re-applies the window each call. No cache holds a price: costs depend on the catalog and are computed per request at summary time. Records keep only the usage fields the math reads (`pricing.slim_usage` — a test fails if a reader consumes a key it would discard). Regenerable (missing/corrupt cache → full reparse). **Bump `_CLAUDE_PARSE_VERSION` / `_CODEX_PARSE_VERSION` / `_GROK_PARSE_VERSION` / `_GEMINI_PARSE_VERSION` on any output-shape change, and `_CLAUDE_STATE_VERSION` on any `_claude_state` shape change** (→ `tests/test_claude_log_store.py::test_state_shape_is_pinned`). **A deadline-cut walk checkpoints and raises — don't revert to all-or-nothing.** `_cached_log_records` (and `_cached_claude_states`, which checkpoints into the hot file only) stops `_CHECKPOINT_MARGIN_SECONDS` before the deadline (so the save lands before the one-shot process kills its daemon thread), saves `{**old_files, **new_files}`, and raises `LogScanIncomplete` (a TimeoutError → `cost_summary_timeout`, and `update_cost_archive` never runs on partial totals). A partial cache is safe (entries are reused only on matching mtime+size); partial records are not. Without the checkpoint, a version bump on a history whose full parse doesn't fit one refresh restarts from zero every refresh and the banner never clears. → `tests/test_accounting.py::test_cut_walk_*`, `::test_cold_cache_converges_*`, `tests/test_backend.py::test_cut_log_scan_*`. `local_gemini_token_summary` routes through the same `_cached_log_records` seam via `walker=_gemini_session_files` — the walker (NOT rglob) prunes the multi-GB `antigravity*` subtrees; keep the prune. → `tests/test_accounting.py::test_parse_cache_*`, `::test_slim_usage_covers_every_key_the_readers_consume`.

**Claude transcripts come from several roots, all feeding ONE summary and ONE store.** `~/.claude/projects` is the primary root; `_claude_extra_roots` adds the roots that exist among `$CLAUDE_CONFIG_DIR/projects`, `<config>/claude/projects` and every `.claude/projects` under `<config>/Claude/local-agent-mode-sessions` (the desktop app's Cowork and agent sessions, at varying depth; `<config>` is `$XDG_CONFIG_HOME` or `~/.config`). A `.jsonl` outside a `.claude/projects` directory there (an audit log) is not a transcript. The discovery walk stops descending at a root, skips plugin/mount/bulk directories and is depth-bounded; one cut by the deadline raises `LogScanIncomplete`, because a partial root list would make a complete walk prune the unreached roots' entries. A store key is the file's absolute path, so roots never collide and the primary root's entries keep their keys and shards; `_shard_of` hashes the two path parts under whichever root holds the file, so a session's main and subagent transcripts share a shard in every root. The per-request dedup is global across roots. A caller-supplied `projects_dir` (tests) reads only that root. → `tests/test_claude_roots.py`.

**Claude parse cache is tail-incremental (`off` + `fp`) — Claude ONLY, and the window end is fixed BEFORE reading.** `_cached_claude_states` extends a changed session JSONL from `off` (end of the last complete line) instead of reparsing it. Invariant: an entry's state is exactly `_claude_state` of the parse of bytes `[0, off)` — it takes `end = _safe_resume_offset(path)` first and `_parse_claude_file(path, start, end)` is bounded to it; never parse to EOF and measure the offset afterwards (that double-stores a final line whose `\n` hasn't landed, and the per-message dedup doesn't cover keyless records). `_tail_parse` is fail-closed → full reparse on shrink, same-size rewrite, or an `fp` mismatch (CRC32 of the 256 bytes before `off` — catches a rewrite that GREW). `_parse_codex_file`/`_parse_grok_file` carry per-line state (`current_model`/`model_by_sid`) so resuming mid-file would mis-attribute models — `_cached_log_records` always parses a file whole. → `tests/test_accounting.py::test_incremental_*`, `::test_grown_rewrite_*`, `::test_unterminated_*`, `::test_append_during_*`, `::test_stateful_parsers_are_not_wired_for_incremental`.

**The Claude cache stores each file's records FOLDED, in a hot/cold store — a refresh writes about what changed.** `_claude_state` folds a file the way `local_claude_token_summary` does (per message key: the first max-output record, earliest/latest epoch second, final flag, visible chars by line uuid; keyless records kept whole), and `_merge_claude_state(state(A), state(B)) == state(A + B)` is what a tail parse relies on. The summary folds the per-file states across files in walk order, so the cross-file dedup by message id stays exact; a message whose lines straddle the window start makes `_claude_state_in_window` re-read that file and fold only its in-window records. `_ClaudeLogStore`: 64 cold shards (`claude_logs.sNN.json`, a session's main and subagent transcripts hash to one shard) plus `claude_logs.hot.json`, which holds whole entries for new/reparsed files and, for a file that only grew, a delta tagged with its cold entry's `off`/`fp` (`base`/`bfp`); an active session costs one small hot-file write per refresh, and only a complete walk past `_CLAUDE_HOT_LIMIT` folds the hot file into the shards its entries belong to. Shards are written before the hot file and a delta whose base no longer matches is dropped on load, so a crash between writes is safe. A cache in the single-file format (`claude_logs.json`) is folded in entry by entry as the walk reaches each file and deleted once a complete walk has taken it all in — never discarded, since a cold reparse of a large history spans many refreshes. → `tests/test_claude_log_store.py`.

**`get_pricing` resolves exact-key-first, then longest `pattern in name`, then longest `name in pattern`.** Unknown non-empty model → provider-family default (not $0); `model=None`/`""` → $0. A match is the model's **own** price only when it is the exact key or a same-model variant of it (pinned date, `[1m]`, `-latest`, `-preview`, `-exp`: `pricing_data._model_base`); a name that only reached a shorter sibling (`claude-fable-5-2` → `claude-fable-5`, `gpt-5.3-codex` → `gpt-5`) still bills at that row but `accounting.pricing.has_catalog_price` is False for it, for every provider, so the model is named in `unpricedModels`. `pricing_data.resolve_pricing` returns `(prices, same_model)`. → `tests/test_pricing_lookup.py::test_a_sibling_match_is_not_a_catalog_price`. `_FALLBACK_PRICING` is what a first run / offline / CI bills from: every current Claude model needs its own exact row with its published cache-read rate copied, never derived as 0.1× input (Opus 5.5 is 0.05×, Fable/Mythos 5.1 0.025×). → `tests/test_pricing_data.py::test_offline_fallback_prices_every_current_claude_model_exactly`. Resolution is **memoized in `_resolve_memo` / `_match_memo`** (keyed by lowercased name) — it's called once per usage record by the local-log summarizers. Only `_install_catalog` swaps the catalog, and it clears the memos. LiteLLM rows of mode `chat` AND `responses` are ingested (the codex, codex-mini and pro models are `responses`). → `tests/test_pricing_data.py`.

**Intro prices end on their own, and a usage bills the rate of its own day.** `pricing_data.LIST_RATE_FROM` maps a model to (date, list rates). The installed catalog and the memos keep the intro row; `get_pricing(model, usage_date)`, `accounting.model_pricing`, `usage_cost_usd` and `usage_split` take the usage's ISO local `YYYY-MM-DD` day (None = today) and `_list_rates_for` returns the list rates from the scheduled date on, but only while the row still carries the intro input rate — a catalog that already moved is left alone. Summarizers that bucket records by day pass that day. → `tests/test_pricing_lookup.py::test_usage_date_picks_the_intro_or_list_rate`. Every scheduled model needs an offline intro row. → `tests/test_pricing_data.py::test_intro_rate_moves_to_list_rate_on_its_date`, `tests/test_enforced_rules.py::test_every_scheduled_list_rate_has_an_intro_row`

**Prompt-length price tiers bill the WHOLE request, for every provider — and only ONE request's prompt can pick one.** Claude Haiku 5.5 costs 5× once a prompt passes 100K tokens (Sonnet 4.5 more past 200K: that tier is LiteLLM-catalog-only, Anthropic's page no longer lists it; kept catalog-driven), GPT-5.5/5.4 more past 272K, Gemini 2.5/3.1 Pro past 200K, xAI Grok 4.x and its coding models from 200K. `pricing_data._long_context_tier` reads every provider's LiteLLM `*_above_<N>k_tokens` fields (lowest N with a positive input and output rate; the anchored patterns skip `_batches`/`_flex`/`_priority`/`_ultrafast`; the combined `cache_creation_input_token_cost_above_1hr_above_<N>k_tokens` is the long 1h write; all-zero tiers are dropped) into `long_context_threshold` = the LARGEST prompt still on the base rates — N·1000, but N·1000−1 for xAI, which bills "at or above" (exactly 200,000 is the tier) — plus `long_input`/`long_output`/`long_cache_read`/`long_cache_write`/`long_cache_write_1h`; a long cache rate LiteLLM omits is the base rate scaled by the input ratio. `accounting.prompt_tier_prices(prices, prompt)` switches EVERY rate, output included, when prompt > threshold — into a new dict, never mutating the memoized catalog entry. Prompt size: `usage_cost_usd` uses input + tool + cache writes (breakdown-derived too) + cache reads (OpenAI/xAI/Gemini cached tokens sit INSIDE input and are not re-added; Gemini's tool-use prompt adds); an Antigravity ledger entry uses `u + c`. Every local-log summarizer prices each record before bucketing and each `:`/`@`/`#` ledger entry is one call, so those tier (a steps row repeating one record, field 9 plus an exact copy at 28.2, is deduped to one call first via `_dedupe_usage_records`; a steps entry still holding several distinct records carries `n` and bills at base rates; a missing `n` means one call); a statusLine `cli:` entry is a CUMULATIVE session total, so `cost_of(e, per_call=False)` bills it at base rates. Never price a day/model/session sum through the tier. Parse caches need no version bump for tiers (records already carry every field the prompt sum reads). The `_FALLBACK_PRICING` row of every model the catalog tiers carries the same keys; Antigravity's Gemini 3.1 Pro bills off the `gemini-3.1-pro` fallback row even online (the catalog only has `-preview`). **`pricing_cache.json` carries `version` = `PRICING_CACHE_VERSION` — bump it on any `_litellm_to_tallybar` output change:** both loaders refuse another version (even as the stale fallback) and `cache_is_current()` makes build_snapshot refetch on that same refresh. → `tests/test_pricing_data.py::test_litellm_*`, `::test_offline_fallback_carries_every_provider_prompt_tier`, `::test_pricing_cache_round_trips_prompt_tiers`, `::test_pre_tier_price_cache_is_never_served`, `tests/test_accounting.py::test_usage_cost_usd_*long_prompt*`, `::test_usage_cost_usd_prompt_*`, `::test_prompt_size_*`, `::test_*_summary_tiers_each_request_not_the_day`, `tests/test_cli_usage.py::test_ledger_calls_pick_their_own_prompt_tier`, `::test_cumulative_cli_entry_bills_at_the_base_rates`, `tests/test_backend.py::test_pre_upgrade_price_cache_is_refetched_at_once`.
